# 分句草稿选区学习入口

日期：2026-10-21。

分句模式每组的可见输入框复用范文选区的同一套操作栏：添加到助手、翻译与学习，以及选中单词或句内片段时的“整句”。只增加入口，不增加后端接口、学习类型或提示词。

## 行为

- 电脑双击选词、鼠标拖选或键盘选择后显示操作栏；手机、平板使用原生选区后显示相同文字的入口。仅选中不请求 AI。
- 添加到助手只准备引用，后续提问才请求 `/api/assistant`；翻译与学习/整句继续打开独立弹层并请求 `/api/analyze`。
- 分析对象是输入框中实际选中的文字，句段上下文及整句范围均来自该输入框当前内容。不会按范文字数替换、修正或映射草稿，也不改变已有范文学习行为。
- “整句”按 UTF-16 原生选区位置扩展所在句，重复句子选择正确的一次；复用原有英文分句规则、选区 2,000 字符上限、缓存、失败重试及 JSON 兜底。
- 点击入口不写入草稿、不触发核对、不改变完成状态或秒表；选择整句只扩展原生高亮范围。
- 隐藏范文不影响草稿入口。已折叠组、核对后隐藏的输入框、正在输入法组合的输入框，以及其他模式中的输入框不提供入口。已核对结果区域继续沿用双击返回编辑的原行为，不作为新选区入口。
- 输入、输入法组合开始、核对、收起分组、重新分组、重练、切换范文或模式使旧选区失效。迟到的响应不能重新打开旧弹层。
- 触屏按钮沿用按下时的选区快照，原生选区因按钮焦点暂时收起时仍可使用；内容被改写、来源被隐藏或移除后快照失效。

## 实现

`sentence-mode.js` 的 `getLearningInputs()` 仅提供当前有效输入框，`app.js` 将它接入 `SelectionTranslation.create` 的 `getAdditionalInputs`。共享控制器负责原生输入选区、上下文、按钮、定位、失效处理和整句扩展。现有的 `getLearningSources()` 仍只负责范文显示区，不改变其映射或调用方。

## 验收清单

- 自动测试：草稿和原文不同、Unicode/UTF-16、重复句子的整句范围、键盘选区、鼠标附近定位、手机按钮快照、只添加引用、不自动请求、隐藏范文仍可用、草稿与秒表保留。
- 来源限制及过期测试：隐藏、折叠、组合输入、核对、编辑、重新分组、模式切换、外部选区与旧请求迟到。
- 桌面浏览器：输入自己的句子，选择单词调用独立学习，再选择“整句”，确认请求为草稿原文；添加到助手及 Ctrl/⌘I 只准备相同引用。
- 手机浏览器：检查相同操作栏、原生范围、独立弹层、添加引用及按钮边界。
- 正式网站：第一次先发布原有助手/快捷提问/兜底/秒表改动；新入口完成后独立提交并二次发布，线上检查分句输入框及原范文入口。
