# 学习助手需求与实现

学习助手复用 Mintlify Astro Starter 的前端组件，在本项目内独立构建，连接主站自己的 AI 后端。练习仍是主页面任务；助手默认收起，按需加载。对话、引用和输入草稿按当前浏览器中的范文与登录身份分别保存。

## 第一版交互

电脑宽屏采用右侧并排面板，支持加宽、缩小和收起；剩余练习宽度不足 900px 时改为覆盖面板。手机采用底部弹层，可展开接近全屏、缩小、下滑关闭。收起不取消生成；切换范文或登录身份会取消旧会话正在进行的生成，保留已收到的内容。

| 入口 | 行为 | AI 请求时机 |
| --- | --- | --- |
| 学习助手 | 打开、收起当前范文对话 | 提问并发送后 |
| 翻译与学习 | 沿用原独立学习弹层，通过 `/api/analyze` 分析选区 | 点击后，不进入助手 |
| 整句 | 扩展为所在完整句子，沿用原独立学习弹层 | 点击后，不进入助手 |
| 添加到助手 | 将选中文字加入待发送引用 | 用户发送问题后 |
| Ctrl / ⌘ + I | 有有效范文选区时添加引用并打开；无选区时开关助手 | 本快捷键不请求 AI |

选区功能沿用原生双击选词、拖选、三击选段和触屏长按选择。全文和分句显示的英文范文均支持，隐藏范文和跨组无效选区不参与学习。单次选区最多 2,000 字符；最多准备 5 段引用，总引用与句段上下文最多 16,000 字符。相同来源选区去重；引用可以移除或展开查看，发送后保留在对应用户消息中。选择文字、添加引用、展开引用、打开或收起助手均不请求 AI。

原“翻译与学习 / 整句”与助手保持独立：原来的提示词、请求、缓存、弹层、展开学习和失败重试均保留，不写入助手对话或改变助手草稿。只有“添加到助手”和 Ctrl / ⌘ + I 将选区作为引用加入助手，添加本身不请求 AI。电脑助手输入框 Enter 发送、Shift+Enter 换行，输入法组合文字的 Enter 不发送；手机 Enter 换行，使用发送按钮提交。页面存在账户、导入等模态对话框时，不接管 Ctrl / ⌘ + I。

## 生成状态与恢复

分句草稿输入框也提供同一组选区入口；分析所选草稿，整句与上下文均来自输入框，不改变范文选区的行为。规则见 [分句草稿选区学习](SENTENCE_INPUT_LEARNING.md)。

输入框上方提供六个按引用推荐的快捷提问：句子拆解、词汇搭配、仿写练习、同义替换、自然改写、写作应用。默认显示 2–3 个，其余放“更多”；点击直接发送，保留输入草稿及其他待发送引用。完整规则和验收记录见 [快捷提问](ASSISTANT_QUICK_QUESTIONS.md)。

- 助手回答默认精简：结论或译文在前，再按需补 1–3 个短要点，通常控制在 150 字以内；必要完整译文或用户要求详细解释时可增加。简单词义用 1–2 句，不自动追加列表、例句或仿写。不寒暄、复述、重复总结或堆砌背景。只讲所引用内容，上下文用于判断语境，不顺带讲解未选内容；例句或仿写按需最多给 1 个。以上为助手模型指引，不在前端截断答案，也不改写原独立学习接口的提示词。
- 生成时发送按钮切换为停止；前后端取消信号会传递到模型请求，停止后保留部分回答并标记已停止。
- 失败在原问答位置提示并提供重试；重新生成同样复用原问题及当时引用，不重复添加用户消息，也不覆盖正在准备的新草稿。
- 失败、停止和刷新中断的回答及其问题不进入后续正常提问的历史上下文。重试会重新发送原问题。
- 收起后生成继续；再次打开不会重复请求。浏览器刷新会中断当前网络请求，恢复记录时标记上次回答中断，可手动重试。
- 时长不足、登录身份变化等由自己的后端校验，不允许借助助手绕过练习权限。前端保留待发送内容，沿用主站账户与时长处理入口。
- 支持 Markdown、表格和代码段、复制回答。模型 HTML 不执行；外部图片不加载，链接只允许明确的 HTTPS 地址。

## 本地数据规则

`assistant-history.js` 以 `mars-ielts-typing:assistant:v1:` 为前缀，按 `guest` 或 `account:<用户ID>`、范文 ID 保存独立记录。保存当前消息、轮次状态、未发送问题和待发送引用。示例范文使用 `sample`，未成功保存的临时范文只保留当前页面内的对话。

最近范文仍沿用原有的 10 篇先进先出规则。范文删除和自动清理时，同步清除本浏览器各身份对应的学习记录；有当前身份的对话时，删除按钮先提示确认。正在显示的范文被删除后可以临时继续查看对话，但延迟保存或旧回答不会重建已删除记录。清空对话只影响当前身份、当前范文，保留范文和练习进度。

每篇记录最多保留 120 条消息、250,000 个 JSON 字符，超过时从最早完整轮次开始清理并提示。消息仅保存文字及经过限制的引用，不保存令牌、原始 HTTP 响应或服务端凭据。关闭存储或容量不足时提示用户，对话仍可在当前页面使用。历史不跨设备同步；主站原有范文和练习进度仍按原规则保存。

保存按 250ms 防抖，页面隐藏、关闭或切换会话时补充刷新保存。新的引用和输入不要求发起 AI 请求后才保存。

## 架构与职责

| 模块 | 职责 |
| --- | --- |
| `app.js` | 发布当前范文 ID、标题、内容；保留现有练习输入、光标、分组与进度 |
| `selection-translation.js` | 获取可靠原文选区、所在句段；提供选区、整句、添加引用三种操作 |
| `assistant-bridge.js` | 主站与 React 模块之间的连接、快捷键、按需加载、身份与范文切换 |
| `assistant/src` | 从 Mintlify 组件改造的面板、移动手势、引用、消息和输入界面 |
| `assistant/src/hooks/useAssistant.ts` | AI SDK 消息状态、发送停止重试、浏览器保存及上下文裁剪 |
| `assistant-history.js` | 本地记录校验、容量限制、按范文清理及身份隔离 |
| `assistant-service.mjs` | 输入校验、学习提示词、DeepSeek 流解析、AI SDK UI 消息流、超时取消 |
| `translation-server.mjs` | 路由、同源与 HTTPS 检查、权限、入口限流、共享并发及静态资源白名单 |

前端独立子项目位于 `assistant/`。React 和 AI SDK 只用于助手，主站保留现有原生 JavaScript。构建生成根目录 `learning-assistant.js`、`learning-assistant.css` 和 `learning-assistant.js.LEGAL.txt`，随源码一起管理并由主站同源加载，不依赖 CDN、Mintlify 账号或托管 API。

原始来源、固定提交和改造范围记录在 [上游来源](../assistant/UPSTREAM.md)。MIT 与 AI SDK Apache 2.0 许可及依赖构建声明保存在源码和发布产物中。

## 后端接口

`POST /api/assistant`，请求头 `Content-Type: application/json`，要求本站 Origin、有效游客或账号权益，以及与当前 Cookie 身份匹配的 `owner`。请求体最大 240,000 字节：

```json
{
  "owner": "guest",
  "article": { "title": "练习范文", "text": "必要的英文范文上下文" },
  "messages": [
    {
      "id": "本轮问题ID",
      "role": "user",
      "parts": [{ "type": "text", "text": "请解释这个词在原句中的含义" }],
      "metadata": {
        "references": [{ "id": "引用ID", "text": "progress", "sentence": "We make progress.", "paragraph": "" }]
      }
    }
  ]
}
```

前端裁剪到近期最多 7 轮、约 65,000 个 JSON 字符，历史回答每条最多 8,000 字符；当前问题与引用始终保留。后端再次校验角色、消息长度、引用和总体内容，客户端不能添加 system/tool 指令。范文背景最多发送开头 12,000 字符，引用另附可靠的所在句段，以支持长范文后部选区。普通问题最多 2,000 字符。

服务继续读取现有私有 `DEEPSEEK_API_KEY` / `DEEPSEEK_API_URL` 或兼容别名，使用 `deepseek-flash`、关闭思考模式。系统提示词在服务端维护；历史与范文仅作为学习材料。助手与原有 AI 共用 3 个并发位和每 IP 每分钟 10 次入口限制，不缓存不同会话的回答。单次生成最多 90 秒、8,192 输出 token、32,000 回答字符。

成功流采用 AI SDK UI Message Stream v1：`start → text-start → text-delta… → text-end → finish → [DONE]`，响应头包含 `x-vercel-ai-ui-message-stream: v1`、`Cache-Control: no-store`、`X-Accel-Buffering: no`。开始前的错误使用安全 JSON；开始后的错误使用 `error` 事件，不把半截回答标记成功。模型响应格式异常、超时、网络断开和取消均释放并发位，原始上游错误正文不会返回浏览器。

反向代理已加入助手专用路由的请求大小限制、关闭响应缓冲及 100 秒读取等待配置；这只是仓库配置，执行部署前不会影响线上。静态服务不提供 `assistant/src`、依赖目录、后端源码或私有配置。

## 构建与测试

```powershell
cd assistant
npm ci
npm run build
npm test
cd ..
node --test tests/*.test.cjs
node translation-server.mjs
```

主站运行不需要安装 React 或 AI SDK 的服务端依赖，构建产物已经包含浏览器需要的依赖。修改助手源文件或样式后必须重新构建。单独的本地浏览器测试服务可运行 `node assistant/tests/fixture-server.mjs`，端口 4174，使用内存账号库和可控的模拟模型，不发送真实短信邮件、不调用真实模型，也不参与部署。

验收清单与实际测试记录见 [学习助手验收](ASSISTANT_QA.md)。
