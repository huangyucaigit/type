# 练习时长支付

本项目负责套餐订单、购买窗口、订单记录、签名业务通知及支付后的时长发放，商户侧支付由 [pay.where.work](https://pay.where.work/docs/) 提供。正式微信 Native 支付已于 2026-10-17 部署并启用，同日通过本应用真实 1 分订单的微信付款、业务通知 ACK、权益到账与重复通知幂等验收。本机预览继续使用模拟支付，不产生扣款，公网不开放模拟成功入口。

## 套餐与权益

| 套餐 | 金额 | 固定时长 |
| --- | --- | --- |
| 月度 | ¥9.90（990 分） | 30 天 |
| 季度 | ¥19.90（1990 分） | 90 天 |
| 年度 | ¥59.90（5990 分） | 365 天 |

所有套餐功能相同，购买的时长从 `max(当前时间, 账户已有截止时间)` 起叠加，不覆盖新手券、渠道券或邀请奖励。有效的游客剩余时间按已有权益规则保留。月度、季度和年度使用表中的固定天数，不按自然月或自然年计算。金额、时长、币种和订单归属由服务端确定，浏览器只提交套餐标识与本次购买请求编号。

## 用户流程

1. 打开“套餐”选择时长；未登录会进入邮箱登录或注册，成功后继续购买。
2. 订单窗口展示服务器确认的套餐、金额、订单号和付款二维码。正式模式使用微信扫一扫付款；本机模拟模式明确标注“不扣款”，点击“模拟支付成功”验证流程，无需微信扫码。
3. 窗口打开且页面可见时自动刷新订单，也可点击“我已完成支付，刷新状态”。支付已确认但权益尚未落库时展示“时长处理中”，不会提前显示到账或要求重复支付。
4. 支付通知验证并提交数据库后，账户时长更新，窗口显示到账结果和有效期。关闭窗口不会取消订单；从账户或套餐窗口的“订单记录”可查看最近 20 笔并继续原订单。
5. 未付款可主动取消。付款码到期只表示不能继续使用该码，不等于支付服务已经关单；先确认关闭旧付款请求，才能在同一业务订单重新获取付款码。关闭与付款并发时，以已确认付款为准。

浏览器仅按账户保存待处理订单号、套餐标识和购买请求编号，以便刷新恢复，不保存密钥、密码或邮件信息。浏览器存储被禁用时仍可下单，并从服务器订单记录恢复。退出或切换账户会停止旧窗口轮询并清除旧账户的显示内容。

## 运行模式与私有配置

`ZIJIAN_PAYMENT_MODE` 支持 `disabled`、`mock`、`live`。真实付款必须同时设置 `ZIJIAN_PAYMENT_MODE=live` 与 `ZIJIAN_ENABLE_REAL_PAYMENTS=1`，并提供完整的支付配置；单独填写密钥不会自动启用真实付款。本机预览使用 `mock`，真实开关为 `0`；正式站点使用 `live` 与真实开关 `1`，以上线配置检查及真实验收记录为准。

模拟提供商在应用进程内运行，不连接商户或微信；同样验证请求和通知签名，持久化订单、付款尝试与通知结果。模拟购买及成功接口只允许本机回环访问；通过公网域名访问不会开放免费自助增加付费时长的入口。正式站点不应使用模拟模式发放用户权益。

部署脚本在使用 `-UpdateSecrets` 同步环境时，会将本地的 `ZIJIAN_PAYMENT_MODE=mock` 转成服务器的 `disabled`，防止把预览模式一起发布。普通部署保留远端现有环境文件；真实模式仍需上述双开关与完整配置，不能通过发布源码隐式启用。

私有配置只放入被忽略的 `.env` 或服务器的 `config/app.env`：

| 名称 | 用途 |
| --- | --- |
| `PAY_BASE_URL` | 支付服务 HTTPS 根地址 |
| `PAY_PROJECT_CODE` | 已开通的项目标识 |
| `PAY_API_KEY_ID`、`PAY_API_SECRET_BASE64` | 本项目向支付服务请求时使用的签名密钥编号与 Base64 密钥 |
| `PAY_NOTIFY_KEY_ID`、`PAY_NOTIFY_SECRET_BASE64` | 验证支付服务业务通知的独立密钥编号与 Base64 密钥 |
| `PAY_NOTIFY_URL` | 本网站业务通知完整 HTTPS 地址，路径为 `/payments/notify` |
| `PAY_NOTIFY_KEYS_JSON` | 可选，通知密钥编号到 Base64 密钥的 JSON 对象，例如 `{"notify_old":"<旧密钥>","notify_new":"<新密钥>"}` |

下载的项目私有配置 `.deploy/pay-project.private.json` 已包含在忽略目录中。不得提交、作为静态资源提供、打印到日志或发送给浏览器。请求签名密钥与通知验证密钥不能混用；配置缺失、错误或真实开关关闭时停止购买，不能回退为无签名真实请求。

通知密钥轮换时先在私有环境中同时接受旧、新编号，再由支付项目切换发送编号，确认旧通知重投结束后移除旧编号。单一 `PAY_NOTIFY_KEY_ID` 与 JSON 中同编号的值必须一致；密钥为至少 32 字节随机值的标准 Base64 编码。不要把 API 签名密钥放入通知密钥集合。

## 订单、通知与恢复

浏览器接口位于 `/api/billing/`，登录用户只能查看和操作自己的订单，写入接口要求本站 CSRF 令牌。公开套餐接口不创建订单，也不启动游客计时。创建购买使用稳定请求编号，网络中断后重试原请求，不另造一笔购买；遇到已有待处理订单会恢复原订单。

服务端通过微信 Native 协议适配器创建、查询、同步和关闭付款尝试。请求签名覆盖 HTTP 方法、原始路径及查询字符串、项目、密钥编号、时间戳、随机数和原始正文摘要；网络结果不明时保留原订单及幂等标识，先查询恢复，不能仅凭超时判定失败。

业务通知地址为 `POST /payments/notify`，不使用浏览器登录 Cookie 或 CSRF 认证，单独验证通知签名、项目、密钥编号、时间窗口及随机数。验签使用收到的原始正文，校验成功后再解析通知；再核对订单、金额、币种、付款尝试和支付交易信息。

支付事实、通知去重和权益发放在同一 SQLite 事务中提交，成功后才返回 `{ eventId, status: "ACK" }`。重复通知不会重复增加时长；数据库提交失败不会返回成功 ACK，等待支付服务重投。查询支付已成功但业务通知尚未完成时保留“处理中”，不得仅凭前端按钮、二维码或上游付款状态直接发放权益。

应用在返回成功通知响应时记录以下审计 JSON，用于把通知事件与 HTTP ACK 对应起来：

```json
{"event":"payment_notification_ack","eventId":"<事件编号>","status":"ACK","httpStatus":200}
```

审计记录不包含签名、请求原文、通知密钥或其他私有凭据。确认真实通知通过时，应同时核对这条记录、对应订单状态与账户有效期，不能只依据浏览器的付款成功提示。

订单、通知和权益记录保存在私有 `auth.sqlite`。更新源码和代码回退不覆盖数据；复制运行中的 SQLite 文件不能替代一致性备份。恢复旧数据前需核对支付服务的付款记录与本地权益，防止漏发或重复发放。部署及备份边界见 [部署与恢复](OPERATIONS.md)。

## 私有订单排查

`payment-admin.mjs` 是可信维护者使用的本地工具，没有公开 HTTP 管理入口。默认读取项目私有 `.env`，数据库默认使用 `ZIJIAN_AUTH_DATA_DIR/auth.sqlite`，未设置目录时为项目 `.data/auth.sqlite`；指定的数据库不存在时拒绝执行，不创建空库。

读取本地订单快照：

```powershell
node payment-admin.mjs status --order ORDER
```

对已确认付款的原订单重新投递业务通知：

```powershell
node payment-admin.mjs retry-notification --order ORDER
```

`ORDER` 替换为需要排查的业务订单号。也可加 `--database <auth.sqlite 的实际路径>` 指定现有数据库。`status` 不查询商户、不创建付款；`retry-notification` 只重投已有已付款订单的通知，不能给未付款订单制造付款事实，不创建新收款、不退款。工具按私有配置选用模拟或真实提供商，真实模式下重投会联系真实支付服务；重复通知仍须通过原有去重与权益幂等校验。

## 固定 1 分真实验收订单

维护者可为数据库中已经存在的账户创建私有验收订单：

```powershell
node payment-admin.mjs create-acceptance --user USER_ID --request STABLE_UUID --database AUTH_SQLITE_PATH
```

将 `USER_ID` 替换为既有账户编号，`STABLE_UUID` 替换为本次验收固定使用的 UUID，`AUTH_SQLITE_PATH` 替换为现有数据库的实际路径；也可省略 `--database` 使用默认数据库。网络结果不明或需要恢复时复用相同 `--request`，不要更换编号创建重复验收单。

验收 SKU 固定为 `acceptance_1fen`、1 分人民币、1 天练习时长，不接受自定义金额、时长或任意 SKU；不出现在公开套餐中，公开下单接口不能购买该 SKU。该命令在真实模式下创建实际付款请求，只有用户使用微信扫码付款、签名业务通知成功提交后才发放时长，创建订单本身不代表付款成功。

对应账户从正常“订单记录”恢复验收订单即可看到 ¥0.01 的付款二维码，并沿用普通订单的查询、关闭、重试和到账展示。验收需记录付款、通知 HTTP 200 ACK、订单到账与账户增加 1 天，再重投同一通知确认有效期没有再次增加；本次已完成这套真实验收，结果如下。

## 验收与当前范围
