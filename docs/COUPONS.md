# 渠道时长券

游客首次开始练习后可连续体验 24 小时。剩余时间旁的“抽免费时长”入口打开新手券转盘，未登录也可先抽，3、4、5、6、7 天各有 20% 机会。结果由服务端保存，关闭、刷新或重复请求都不会重抽；抽奖本身不开始游客计时、不发放时长，未领取结果没有额外失效期限。

点击“注册并领取 X 天”或“已有账号登录领取”后，注册或登录成功时按资格自动领取，立即生效，无需二次领取；普通注册仍不自动领券。已登录且符合资格的账号也可先抽再领。每个账号、每个浏览器各限一份新手奖励，账号须在注册后 7 天内领取，领取后隐藏转盘入口。领取时保留并一次性转入尚未消耗的游客体验，原有叠加和去重规则不变。渠道券独立于新手奖励，用于小红书等渠道活动。

## 兑换与叠加

- 渠道券需要先登录，兑换成功立即生效，没有券包或二次使用步骤。
- 同账号、同活动只能兑换一次。同一活动即使有多个渠道码，也不能重复领取；各渠道码共享该活动的总兑换数量。
- 不同活动可以叠加，也可以与新手奖励、已有会员时长叠加。到期时间按 `max(服务端当前时间, 账号当前到期时间) + 券天数 × 24 小时` 计算。
- 已过期的账号从兑换成功时开始计时。未到期的账号从原到期时间继续顺延，退出登录不会暂停计时。
- 活动截止时间只影响尚未兑换的券，已兑换的时长继续有效。停用活动阻止后续兑换，也不会撤销已兑换时长。
- 第一版使用公用活动码，不提供一次性个人券码、券包或网页管理后台。

## 私有管理工具

在运行应用的可信服务器环境中使用 `coupon-admin.mjs`。该文件属于服务端维护工具，不作为网站静态文件开放。它不会发送短信或邮件，也不会调用支付服务。

工具与应用一样会读取仓库 `.env`，默认使用相同的 SQLite 数据库：设置了 `ZIJIAN_AUTH_DATA_DIR` 时为该目录下的 `auth.sqlite`，否则为仓库 `.data/auth.sqlite`。数据库选择优先级为显式 `--database`、已有进程环境、`.env`、默认路径。操作前确认连接的是预期环境。数据库及其 `-wal`、`-shm` 文件不要公开或提交到 Git。

以下仅为配置示例，运行创建命令才会建立活动。请自行替换活动 ID、期限、数量和兑换码，并确认日期仍有效：

```json
{
  "id": "xiaohongshu-autumn",
  "title": "小红书 7 天体验活动",
  "days": 7,
  "startsAt": "2026-10-20T00:00:00+08:00",
  "endsAt": "2026-11-01T00:00:00+08:00",
  "maxRedemptions": 200,
  "codes": [
    { "code": "EXAMPLE-XHS-7", "channel": "小红书" },
    { "code": "EXAMPLE-DY-7", "channel": "抖音" }
  ]
}
```

将配置保存在私有文件（例如 `.deploy/campaign-autumn.json`），再执行：

```powershell
node coupon-admin.mjs create --file .deploy/campaign-autumn.json
node coupon-admin.mjs list
node coupon-admin.mjs disable xiaohongshu-autumn
node coupon-admin.mjs enable xiaohongshu-autumn
```

需要显式选择其他环境时，每个命令都支持 `--database <数据库路径>`，例如：

```powershell
node coupon-admin.mjs list --database D:/private/zijian/auth.sqlite
```

创建成功时会输出活动信息和可分发的兑换码；列表及启停命令只输出统计，不显示原始兑换码。创建失败不留下半个活动；活动 ID 或兑换码已存在时会报冲突，不会覆盖既有数据。启停活动也保留兑换记录及已发放时长。进程退出码为 `0`（成功）、`1`（配置或操作失败）、`2`（命令参数错误）。

## 配置规则

| 字段 | 规则 |
| --- | --- |
| `id` | 必填，3–64 位英文字母、数字、下划线或短横线；区分大小写 |
| `title` | 必填，去除前后空格后 1–100 个字符 |
| `days` | 必填，1–365 的整数；每天按连续 24 小时计算 |
| `startsAt` | 可选，不填时以服务端创建时间开始；填写时必须是含时区及秒的 ISO 日期 |
| `endsAt` | 必填，含时区及秒的 ISO 日期，必须晚于开始时间 |
| `maxRedemptions` | 必填，整个活动的总兑换上限，1–1,000,000 的整数 |
| `codes` | 必填，1–1,000 个 `{ "code", "channel" }` 对象 |
| `code` | 去除前后空格并转大写；3–64 位英文字母、数字、下划线或短横线；全局唯一 |
| `channel` | 去除前后空格后 1–64 个字符，用于统计兑换来源 |

用户输入兑换码时同样忽略大小写和前后空格，内部空格不会忽略。所有时间、兑换资格、活动数量及账号有效期由服务端判断，不使用客户端时钟。统计中的渠道只表示用户兑换了哪个渠道码，不代表已验证用户实际来自该平台。
